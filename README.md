# Бот напоминаний об оплате подписки

Телеграм-бот, который следит за сроками подписок и напоминает об оплате.
Админка встроена в самого бота и доступна только твоему аккаунту.

## Что умеет

**Для пользователя:**
- `/start` — приветствие с просьбой не отключать уведомления, затем запрос имени
- напоминания об оплате: за 3 дня, за 1 день, в день окончания и раз в день при просрочке
- кнопка «💳 Я оплатил» с выбором срока: 1, 2, 3 или 4 месяца
- `/status` — сколько осталось до конца подписки

**Для тебя (админа):**
- заявка на оплату приходит в личку с кнопками «✅ Подтвердить» / «❌ Отклонить» —
  подтверждение сразу продлевает подписку и уведомляет пользователя
- `/users` — список всех пользователей, отсортированный «кто ближе к окончанию»,
  с пометками: ⏳ скоро истекает, 🔴 просрочено, ⚪️ без даты
- карточка пользователя: изменить дату вручную или продлить на 1–4 месяца одной кнопкой
- `/pending` — заявки, ожидающие ответа
- `/find Иван` — поиск по имени, @username или ID
- `/stats` — сводка, `/audit` — журнал изменений
- `/runcheck` — прогнать проверку подписок прямо сейчас (для теста)
- уведомление о каждом новом пользователе — чтобы не забыть выставить ему дату

## Как это работает

Каждый день в 12:00 (таймзона настраивается) бот проверяет все подписки и
рассылает напоминания. Отправленные напоминания записываются в базу, поэтому:

- перезапуск бота или перезагрузка VPS **не приведут** к повторной рассылке;
- если VPS был выключен в 12:00, бот **догонит** пропущенную проверку при старте
  (cron-библиотеки сами пропущенный запуск не выполняют);
- заблокировавший бота пользователь помечается в базе, и рассылка не падает из-за него.

Подтверждение оплаты продлевает подписку от текущей даты окончания, а если
подписка уже просрочена — от сегодняшнего дня, чтобы не дарить прошедшие дни.
Прибавление месяцев ограничивает день последним днём месяца: 31 января + 1 месяц
= 28 февраля (SQLite-арифметика здесь ошибается и даёт 3 марта).

## Установка на VPS (Ubuntu)

### 1. Подготовка

```bash
# Node.js 22 (нужна версия не ниже 20.6 из-за --env-file)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# Отдельный пользователь для бота — не запускай от root
sudo useradd -r -m -d /opt/vpnbot -s /bin/bash vpnbot
```

### 2. Файлы проекта

```bash
# Скопируй проект в /opt/vpnbot (например, через scp с локальной машины):
#   scp -r ./bot user@ваш-сервер:/tmp/bot
sudo cp -r /tmp/bot/. /opt/vpnbot/
sudo chown -R vpnbot:vpnbot /opt/vpnbot

cd /opt/vpnbot
sudo -u vpnbot npm ci --omit=dev
```

### 3. Настройка

```bash
sudo -u vpnbot cp .env.example .env
sudo -u vpnbot nano .env
```

Заполни два обязательных поля:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `ADMIN_ID` — твой numeric id, узнать у [@userinfobot](https://t.me/userinfobot)

**Важно:** после запуска бота обязательно нажми у него `/start` со своего
аккаунта. Telegram не разрешает боту писать первым тому, кто с ним не начинал
диалог — без этого заявки на оплату до тебя не дойдут.

### 4. Автозапуск

```bash
sudo cp /opt/vpnbot/deploy/vpnbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vpnbot

# Проверка
sudo systemctl status vpnbot
sudo journalctl -u vpnbot -f
```

### 5. Резервные копии

```bash
# Ежедневно в 04:00, копии старше 30 дней удаляются
sudo -u vpnbot crontab -e
```

Добавь строку:

```
0 4 * * * cd /opt/vpnbot && /usr/bin/node --env-file=.env src/backup.js >> /opt/vpnbot/backup.log 2>&1
```

Копия делается через SQLite backup API — она согласована даже на работающем
боте (простое `cp` файла базы в режиме WAL может дать неполный снимок).

## Настройки в `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота (обязательно) |
| `ADMIN_ID` | — | Твой numeric telegram id (обязательно) |
| `TZ_NAME` | `Europe/Moscow` | Таймзона ежедневной проверки |
| `REMIND_HOUR` | `12` | Час рассылки напоминаний |
| `REMIND_MINUTE` | `0` | Минута рассылки |
| `DB_FILE` | `./data/bot.db` | Путь к файлу базы |

Таймзона задаётся явно и не зависит от системной — смена времени на сервере
не сдвинет рассылку.

## Локальный запуск

```bash
npm install
cp .env.example .env    # заполни BOT_TOKEN и ADMIN_ID
npm start
```

Тесты (26 проверок, без внешних зависимостей):

```bash
npm test
```

## Обновление кода

```bash
cd /opt/vpnbot
sudo -u vpnbot git pull          # или заново скопируй файлы
sudo -u vpnbot npm ci --omit=dev
sudo systemctl restart vpnbot
```

База при обновлении не трогается: схема создаётся через
`CREATE TABLE IF NOT EXISTS` и версионируется через `PRAGMA user_version`.

## Структура проекта

```
src/
  index.js            точка входа: запуск бота, cron, корректное завершение
  config.js           чтение и проверка .env
  reminders.js        ежедневная проверка подписок и рассылка
  keyboards.js        клавиатуры и кодирование callback_data
  backup.js           резервное копирование базы
  handlers/
    user.js           /start, ввод имени, «Я оплатил», статус
    admin.js          админ-панель: список, карточки, заявки, даты
  lib/
    db.js             схема БД и все запросы
    dates.js          работа с датами (месяцы, разница в днях, таймзона)
    texts.js          все тексты сообщений и подписи кнопок
deploy/
  vpnbot.service      systemd-юнит
  backup.sh           бэкап через утилиту sqlite3 (альтернатива src/backup.js)
test/
  bot.test.js         тесты
```

Тексты сообщений собраны в `src/lib/texts.js` — менять формулировки можно там,
не заглядывая в логику.

## Диагностика

**Бот не пишет мне о заявках.** Нажми `/start` у бота со своего аккаунта и
проверь, что `ADMIN_ID` — это именно твой id (а не id бота).

**Не пришло напоминание.** Посмотри `/stats` — там дата последней проверки.
Затем `sudo journalctl -u vpnbot | grep напоминание`. Каждая отправка пишется
в лог. Помни, что за 2 и 4 дня бот молчит намеренно — только 3, 1, 0 и просрочка.

**Напоминание пришло дважды.** Такого быть не должно: запись в
`sent_notifications` защищена уникальным ключом. Если это случилось — вероятно,
запущено два экземпляра бота (например, systemd и вручную одновременно).
Проверь: `ps aux | grep "src/index.js"`.

**Бот падает при старте.** Он специально не запускается при неверном `.env` и
печатает, что именно не так: `sudo journalctl -u vpnbot -n 30`.
